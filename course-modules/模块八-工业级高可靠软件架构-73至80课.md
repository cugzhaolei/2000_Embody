## 第73课 有限状态机任务调度设计
1.业务背景：机器人任务有明确的阶段转换(空闲→导航→抓取→返回→充电)，FSM是任务调度的标准模式。
2.底层原理：FSM(Finite State Machine)——(S, E, T, s0, F)五元组：状态集S、事件集E、转移函数T、初始状态s0、终态集F。Moore型(输出仅依赖状态) vs Mealy型(输出依赖状态+事件)。层级FSM(HFSM)：状态内嵌套子状态机。ROS2实现：rclcpp_lifecycle + 自定义FSM框架 或 FlexBE。
3.硬件方案：N/A。
4.软件实现：Python FSM框架。
```python
from enum import Enum, auto

class RobotState(Enum):
    IDLE = auto()
    NAVIGATING = auto()
    PICKING = auto()
    RETURNING = auto()
    CHARGING = auto()
    ERROR = auto()

class RobotFSM:
    TRANSITIONS = {
        (RobotState.IDLE, "start_task"): RobotState.NAVIGATING,
        (RobotState.NAVIGATING, "arrived"): RobotState.PICKING,
        (RobotState.NAVIGATING, "nav_failed"): RobotState.ERROR,
        (RobotState.PICKING, "picked"): RobotState.RETURNING,
        (RobotState.PICKING, "pick_failed"): RobotState.ERROR,
        (RobotState.RETURNING, "returned"): RobotState.IDLE,
        (RobotState.ERROR, "reset"): RobotState.IDLE,
        (RobotState.IDLE, "low_battery"): RobotState.CHARGING,
        (RobotState.CHARGING, "charged"): RobotState.IDLE,
    }

    def __init__(self):
        self.state = RobotState.IDLE

    def trigger(self, event: str):
        key = (self.state, event)
        if key in self.TRANSITIONS:
            old = self.state
            self.state = self.TRANSITIONS[key]
            print(f"FSM: {old.name} --[{event}]--> {self.state.name}")
        else:
            print(f"FSM: Invalid transition from {self.state.name} on event '{event}'")
```
5.Demo：FSM状态转换图+ROS2 FSM节点+状态可视化。
6.数据流：外部事件 → FSM转移判断 → 状态更新 → 触发对应行为。
7.调试手段：日志打印状态转换；ros2 topic echo /robot_state 监控当前状态。
8.故障：FSM陷入ERROR无法恢复——根因：缺少ERROR→IDLE的恢复路径；修复：增加自动恢复或人工重置事件。
9.工业案例：某AMR使用HFSM(顶层调度FSM+导航子FSM+抓取子FSM)，3层状态机管理复杂任务流。
10.面试题：FSM五元组定义？Moore与Mealy型区别？HFSM如何解决状态爆炸？

## 第74课 行为树BT复杂业务流程管理
1.业务背景：FSM状态数随业务复杂度指数增长，行为树(BT)以树形结构组合原语，可扩展性更强。
2.底层原理：BT(Behavior Tree)——节点类型：(1)Sequence(序列)：子节点依次执行，任一失败则整体失败；(2)Fallback(选择)：子节点依次尝试，任一成功则整体成功；(3)Action(动作)：执行具体操作(导航/抓取)；(4)Condition(条件)：检查状态(电量/位置)；(5)Decorator(装饰)：修饰子节点(重试/延时/反转)。Nav2已内置BehaviorTree CPP。
3.硬件方案：N/A。
4.软件实现：Nav2行为树XML示例。
```xml
<root main_tree_to_execute="MainTree">
  <BehaviorTree ID="MainTree">
    <Sequence name="navigate_and_pick">
      <Fallback>
        <Condition ID="BatteryOK" min_battery="20"/>
        <Action ID="GoCharge"/>
      </Fallback>
      <Action ID="NavigateToPose" goal="{pick_pose}"/>
      <RetryNode num_attempts="3">
        <Sequence>
          <Action ID="DetectObject"/>
          <Action ID="PickObject"/>
        </Sequence>
      </RetryNode>
      <Action ID="NavigateToPose" goal="{place_pose}"/>
      <Action ID="PlaceObject"/>
    </Sequence>
  </BehaviorTree>
</root>
```
5.Demo：BehaviorTree CPP V4可视化+Nav2自定义BT节点+Groot编辑器。
6.数据流：BT tick信号 → 节点状态(SUCCESS/FAILURE/RUNNING)→父节点组合→任务流程。
7.调试手段：Groot实时可视化BT执行状态；ros2 topic echo /behavior_tree_log。
8.故障：BT无限循环——根因：Fallback中Condition始终返回FAILURE，Action始终返回RUNNING；修复：增加超时Decorator。
9.工业案例：Nav2默认BT=Recovery+Planning+Control三层Fallback，任一阶段失败自动尝试恢复。
10.面试题：BT的Sequence/Fallback语义？BT与FSM的优缺点对比？

## 第75课 插件化模块化架构设计

```python
# base_chassis_driver.py (抽象接口)
class ChassisDriver:
    def connect(self) -> bool: ...
    def set_velocity(self, vx, vy, omega) -> None: ...
    def get_odometry(self) -> dict: ...

# differential_chassis.py (差速底盘插件)
class DifferentialChassis(ChassisDriver):
    def connect(self) -> bool:
        return self.can_bus.connect()
    def set_velocity(self, vx, vy, omega):
        left, right = self._diff_kinematics(vx, omega)
        self.can_bus.send_motor_cmd(left, right)
```

8.故障：插件加载失败——根因：plugins.xml路径或类名错误；修复：检查xml注册和export标签。

## 第76课 分级日志系统与故障记录方案
1.业务背景：7×24小时运行的机器人必须有完善的日志系统，故障时能回溯定位根因。
2.底层原理：ROS2日志——5级：DEBUG→INFO→WARN→ERROR→FATAL；输出目标：console/rosout话题/log文件；ros2_logging配置：按包/节点设置不同级别。日志持久化：ros2 bag录制话题数据；rotating_file_sink按大小/时间滚动。故障记录：异常时自动保存现场(传感器快照+节点状态+TF树+日志尾部)。
3.硬件方案：N/A。
4.软件实现：ROS2分级日志+故障快照。
```python
class FaultRecorder:
    """故障现场快照记录"""
    def __init__(self, node):
        self.node = node
        self.snapshot_dir = "/var/log/robot/faults"

    def capture(self, fault_code: str):
        """捕获故障现场"""
        import datetime, json
        timestamp = datetime.datetime.now().strftime("%Y%m%d_%H%M%S")
        snapshot = {
            "timestamp": timestamp,
            "fault_code": fault_code,
            "odom": self._get_latest_msg("/odom"),
            "battery": self._get_latest_msg("/battery_state"),
            "nav_state": self._get_latest_msg("/behavior_tree_log"),
            "joint_states": self._get_latest_msg("/joint_states"),
        }
        path = f"{self.snapshot_dir}/fault_{timestamp}_{fault_code}.json"
        with open(path, 'w') as f:
            json.dump(snapshot, f, indent=2, default=str)
        self.node.get_logger().error(f"Fault snapshot saved: {path}")
```

## 第77课 配置文件统一管理与热加载
1.业务背景：机器人有大量配置文件(导航参数/传感器标定/硬件参数)，需要统一管理和运行时热加载。
2.底层原理：配置管理——(1)YAML分层：default.yaml(出厂)→site.yaml(现场)→override.yaml(临时)，后者覆盖前者；(2)ROS2 Parameters：通过--params-file加载YAML；(3)动态重配置：ros2 param set + on_parameter_event回调实时生效；(4)版本管理：配置文件入Git，变更可追溯。热加载：修改YAML→触发callback→更新运行参数，无需重启节点。
3.硬件方案：N/A。
4.软件实现：分层配置加载+参数回调。
```python
class ConfigManager:
    """分层配置管理"""
    def __init__(self, node, config_paths: list):
        self.node = node
        self.config = {}
        for path in config_paths:
            if os.path.exists(path):
                with open(path) as f:
                    self.config.update(yaml.safe_load(f))
        # 声明参数并设置回调
        for key, value in self.config.items():
            self.node.declare_parameter(key, value)
        self.node.add_on_set_parameters_callback(self._on_param_change)

    def _on_param_change(self, params):
        for p in params:
            self.node.get_logger().info(f"Config updated: {p.name} = {p.value}")
        return SetParametersResult(successful=True)
```

6.数据流：YAML文件 → Launch加载 → 节点参数 → 运行时set → 回调更新。
7.调试手段：ros2 param dump导出当前配置对比；git diff查看配置变更。
8.故障：配置修改后节点行为未变——根因：未实现参数回调或硬编码了参数值；修复：使用get_parameter替代硬编码。

## 第78课 异常捕获、自动复位、故障自愈机制
1.业务背景：工业机器人不能因一次异常就停机，需要自动检测→复位→重试的自愈能力。
2.底层原理：异常分级——(1)可恢复异常：通信超时→自动重连、导航失败→重规划、传感器数据异常→降级运行；(2)不可恢复异常：硬件故障→安全停机+告警。自愈策略：Circuit Breaker模式(连续N次失败后断开，冷却后重试)、指数退避重试、健康检查心跳。Nav2的Recovery Server：spin→clear_costmap→wait→重新规划。
3.硬件方案：N/A。
4.软件实现：Circuit Breaker + 自动复位。
```python
class CircuitBreaker:
    """熔断器模式"""
    def __init__(self, failure_threshold=3, recovery_timeout=30.0):
        self.failure_count = 0
        self.threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.last_failure_time = 0
        self.state = "CLOSED"  # CLOSED / OPEN / HALF_OPEN

    def call(self, func, *args, **kwargs):
        if self.state == "OPEN":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "HALF_OPEN"
            else:
                raise Exception("Circuit breaker OPEN")
        try:
            result = func(*args, **kwargs)
            self.failure_count = 0
            self.state = "CLOSED"
            return result
        except Exception as e:
            self.failure_count += 1
            self.last_failure_time = time.time()
            if self.failure_count >= self.threshold:
                self.state = "OPEN"
            raise
```
5.Demo：Circuit Breaker演示+Nav2 Recovery行为树+故障自愈流程图。
6.数据流：操作调用 → 熔断器判断 → 正常执行/拒绝/半开试探 → 成功/失败更新状态。
7.调试手段：日志监控熔断器状态转换；手动触发故障验证自愈流程。
8.故障：自愈后仍然失败→再次自愈→死循环——根因：根因未消除，自愈只是重试；修复：限制最大重试次数，超过则升级为不可恢复故障。
9.工业案例：某AMR导航失败后自动clear_costmap+重规划3次，3次仍失败则回退充电桩。
10.面试题：Circuit Breaker三种状态？自愈策略的指数退避原理？如何防止自愈死循环？

## 第79课 多线程、多进程资源隔离方案
1.业务背景：导航算法、视觉推理、大模型推理等模块延迟差异大，必须隔离避免相互阻塞。
2.底层原理：隔离策略——(1)多线程(MultiThreadedExecutor)：ROS2单进程多线程，共享内存高效，但GIL限制CPU并行；(2)多进程：不同模块独立进程，通信通过DDS/共享内存，一个崩溃不影响其他；(3)容器化：Docker容器隔离，限制CPU/内存/GPU资源，适合多AI模型并行。GPU隔离：CUDA Multi-Process Service(MPS)或独立GPU上下文。
3.硬件方案：本项目——导航(进程1, CPU核0-2) + 视觉(进程2, CPU核3+GPU) + VLA推理(进程3, GPU共享) + 通信(进程4, CPU核4)。
4.软件实现：ROS2 MultiThreadedExecutor + Docker Compose。

## 第80课 CPU、内存、网络延迟性能优化手段
1.业务背景：机器人实时性要求高(导航50Hz,控制1kHz)，性能优化是上线前的必经环节。
2.底层原理：优化方法——(1)CPU：taskset绑核、PREEMPT_RT实时内核、nice/ionice优先级、SIMD向量化(AVX/SSE)、零拷贝(DDS SHM)；(2)内存：预分配缓冲池避免运行时malloc、内存映射(mmap)共享数据、避免频繁GC(Python用subprocess换C++)；(3)网络：Jumbo Frame(9000MTU)降低大帧开销、UDP多播替代TCP单播、共享内存替代网络传输、QoS BestEffort降低重传。Profiling工具：perf/top/htop/nvprof/valgrind。
3.硬件方案：工控机i7-12700H + 16GB RAM + RTX3060 + 千兆以太网。
4.软件实现：性能优化脚本。
```bash

# 网络优化: 启用 Jumbo Frame

# DDS 共享内存 (FastDDS)
export FASTRTPS_DEFAULT_PROFILES_FILE=/config/fastdds_shm.xml

# GPU 推理优化 (TensorRT)
trtexec --onnx=model.onnx --saveEngine=model.trt --fp16
```
