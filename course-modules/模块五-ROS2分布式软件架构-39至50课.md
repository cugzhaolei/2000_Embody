## 第42课 节点开发规范
1.业务背景：节点是ROS2基本运行单元，开发规范直接影响代码质量和可维护性。
2.底层原理：ROS2 Node(rclpy/rclcpp)——节点生命周期：构造→参数声明→订阅/发布/定时器注册→spin→销毁；参数(Parameters)：运行时可配置，支持动态重配置；组件(Component)：可被组合到单一进程减少通信开销。编码规范：命名(node_lowercase)、日志(rclpy logging)、异常处理(try/except+降级)。
3.硬件方案：N/A。
4.软件实现：ROS2 Python节点模板。
```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class TemplateNode(Node):
    def __init__(self):
        super().__init__('template_node')
        # 声明参数
        self.declare_parameter('publish_rate', 10.0)
        self.declare_parameter('topic_name', 'output')

        # 创建发布者
        rate = self.get_parameter('publish_rate').value
        topic = self.get_parameter('topic_name').value
        self.pub = self.create_publisher(String, topic, 10)
        self.timer = self.create_timer(1.0/rate, self.timer_callback)

    def timer_callback(self):
        msg = String()
        msg.data = "Hello from template node"
        self.pub.publish(msg)
        self.get_logger().info(f'Published: {msg.data}')

def main(args=None):
    rclpy.init(args=args)
    node = TemplateNode()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()
```
5.Demo：节点模板+参数动态配置+日志等级切换。
6.数据流：参数配置 → 节点初始化 → 定时器/订阅触发 → 数据处理 → 发布。
7.调试手段：ros2 node list/info查看节点；ros2 param get/set动态调参；ros2 run --log-level debug设置日志。
8.故障：节点启动后立即退出——根因：未调用rclpy.spin()，主线程直接结束；修复：确保spin阻塞主线程。

## 第43课 Topic话题通信与数据流设计
1.业务背景：话题是ROS2最核心的通信机制，设计合理的话题数据流是系统架构的基础。
2.底层原理：Topic——发布/订阅模式，多对多通信；消息类型：std_msgs(基础)、geometry_msgs(几何)、sensor_msgs(传感器)、nav_msgs(导航)、自定义.msg；QoS策略决定传输行为。数据流设计原则：(1)单向流动，避免环形依赖；(2)消息粒度适中，不过大(影响延迟)也不过小(增加开销)；(3)命名规范：/namespace/entity/attribute。
3.硬件方案：N/A。
4.软件实现：自定义消息+话题发布/订阅。
```python
# msg/RobotStatus.msg
# float32 x
# float32 y
# float32 battery
# string state

from my_robot_msgs.msg import RobotStatus

class StatusPublisher(Node):
    def __init__(self):
        super().__init__('status_publisher')
        self.pub = self.create_publisher(RobotStatus, '/robot/status', 10)
        self.timer = self.create_timer(0.1, self.publish_status)

    def publish_status(self):
        msg = RobotStatus()
        msg.x = 1.0
        msg.y = 2.0
        msg.battery = 85.0
        msg.state = "navigating"
        self.pub.publish(msg)
```
5.Demo：自定义消息定义+话题通信+ros2 topic hz/bw/echo验证。
6.数据流：传感器→预处理话题→算法节点→决策话题→执行器。
7.调试手段：ros2 topic list/echo/hz/bw；rqt_graph可视化节点-话题拓扑。
8.故障：话题收到数据但频率远低于预期——根因：QoS不匹配(Reliable vs BestEffort)；修复：统一发布端和订阅端QoS。
9.工业案例：某项目传感器话题Reliable策略导致积压延迟，改为BestEffort+KeepLast(1)后延迟从100ms降至5ms。

## 第44课 Service同步调用接口
1.业务背景：某些操作需要请求-响应模式（如触发标定、查询状态），不适合用话题，需要Service。
2.底层原理：Service——请求/响应模式，一对一同步通信；.srv文件定义Request和Response；调用方式：call(阻塞) / call_async(异步回调)；适用场景：低频、需确认的操作（触发/查询/配置）。注意：Service回调中不可执行耗时操作，否则阻塞executor。
3.硬件方案：N/A。
4.软件实现：自定义服务+服务端/客户端。
```python
# srv/TriggerCalibration.srv
# ---
# bool success
# string message

from my_robot_msgs.srv import TriggerCalibration

class CalibrationServer(Node):
    def __init__(self):
        super().__init__('calibration_server')
        self.srv = self.create_service(
            TriggerCalibration, '/robot/calibrate', self.calibrate_callback)

    def calibrate_callback(self, request, response):
        # 执行标定逻辑
        response.success = True
        response.message = "Calibration completed"
        return response
```
5.Demo：Service服务端+客户端+ros2 service call/list测试。
6.数据流：客户端请求 → 服务端回调处理 → 返回响应。
7.调试手段：ros2 service list/type/call手动调用服务；ros2 service call /robot/calibrate std_srvs/srv/Trigger。
8.故障：Service调用超时无响应——根因：回调函数执行耗时操作阻塞executor；修复：耗时操作放线程池，回调立即返回。
9.工业案例：某机械臂标定服务执行需30秒，改为异步+Action模式避免阻塞。
10.面试题：Service与Topic区别？Service回调中为什么不能执行耗时操作？

## 第45课 Action异步任务动作接口
1.业务背景：长时间运行的任务（导航到目标点、机械臂抓取）需要进度反馈和取消能力，Action是最佳选择。
2.底层原理：Action——请求/反馈/结果三段式通信；.action文件定义Goal/Feedback/Result；底层由3个话题+2个服务实现；支持：发送目标→接收周期反馈→目标完成/取消/中止。生命周期：ACCEPTED→EXECUTING→SUCCEEDED/ABORTED/CANCELED。
3.硬件方案：N/A。
4.软件实现：Action服务端(导航示例)+客户端。
```python
# action/NavigateTo.action
# float32 target_x
# float32 target_y
# ---
# bool success
# string message
# ---
# float32 distance_remaining

from nav2_msgs.action import NavigateToPose

class NavigationActionServer(Node):
    def __init__(self):
        super().__init__('nav_action_server')
        self._action_server = ActionServer(
            self, NavigateToPose, '/navigate_to_pose',
            execute_callback=self.execute_callback)

    async def execute_callback(self, goal_handle):
        feedback = NavigateToPose.Feedback()
        for i in range(100):
            if goal_handle.is_cancel_requested:
                goal_handle.canceled()
                return NavigateToPose.Result(success=False, message="Canceled")
            feedback.distance_remaining = 10.0 * (1 - i/100)
            goal_handle.publish_feedback(feedback)
            await asyncio.sleep(0.1)
        goal_handle.succeed()
        return NavigateToPose.Result(success=True, message="Arrived")
```
5.Demo：Action服务端+客户端+ros2 action send_goal测试+取消目标。
6.数据流：客户端发送Goal → 服务端接收并执行 → 周期发布Feedback → 完成返回Result。
7.调试手段：ros2 action list/send_goal；rqt_action可视化Action状态。
8.故障：Action目标被意外取消——根因：多个客户端发送同名Goal，后到的覆盖了前者；修复：使用GoalUUID区分不同目标。
9.工业案例：Nav2导航使用NavigateToPose Action，调度系统可实时获取剩余距离并取消任务。
10.面试题：Action与Service/Topic区别？Action的Goal/Feedback/Result机制？

## 第46课 TF多坐标系变换完整链路
1.业务背景：机器人有base_link、laser、camera、arm_base、end_effector等多个坐标系，所有感知和控制都依赖正确的TF变换。
2.底层原理：TF2——树形坐标系结构，每个frame有一个parent；变换链：base_link→laser(静态)、base_link→camera(静态)、base_link→arm_base(静态)、arm_base→end_effector(动态，随关节变化)；发布方式：StaticTransformPublisher(静态)、tf2_ros.TransformBroadcaster(动态)；查询：tf2_ros.BufferClient.lookup_transform(target, source, time)。
3.硬件方案：N/A。
4.软件实现：TF发布+查询。
```python
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped

class TFPublisher(Node):
    def __init__(self):
        super().__init__('tf_publisher')
        self.br = TransformBroadcaster(self)
        self.timer = self.create_timer(0.05, self.publish_tf)

    def publish_tf(self):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'base_link'
        t.child_frame_id = 'laser'
        t.transform.translation.x = 0.3
        t.transform.rotation.w = 1.0
        self.br.sendTransform(t)
```
5.Demo：RViz可视化TF树+tf2_ros查询示例+tf2_tools调试。
6.数据流：各节点发布TF → tf2 Buffer聚合 → 查询节点lookup_transform。
7.调试手段：rviz2显示坐标系；ros2 run tf2_tools view_frames生成PDF；ros2 topic echo /tf查看变换数据。
8.故障：lookup_transform报"extrapolation into past"——根因：查询时间戳早于可用TF数据；修复：确保时间戳同步，使用timeout参数等待。
9.工业案例：某机械臂抓取失败——根因：camera→base_link的TF偏移2cm，重新标定后精度恢复。

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():

        # 参数声明
        DeclareLaunchArgument('use_sim', default_value='false'),
        # 底盘驱动

## 第49课 生命周期Lifecycle高可靠节点开发
1.业务背景：工业机器人要求节点启动有严格的状态管理，出错可恢复，Lifecycle节点提供了标准化的状态机。
2.底层原理：Lifecycle Node状态机——Unconfigured→Inconfigured→Inactive→Active→Finalized；转换事件：on_configure(初始化资源)→on_activate(开始工作)→on_deactivate(暂停)→on_cleanup(释放资源)→on_shutdown(关闭)。好处：可控的启停顺序、错误恢复、热替换。
3.硬件方案：N/A。
4.软件实现：Lifecycle节点模板。
```python
from rclpy.lifecycle import LifecycleNode, LifecycleState, TransitionCallbackReturn

class SafeDriverNode(LifecycleNode):
    def __init__(self):
        super().__init__('safe_driver', enable_logger_service=True)

    def on_configure(self, state: LifecycleState) -> TransitionCallbackReturn:
        """初始化硬件连接"""
        try:
            self.device = connect_hardware()
            return TransitionCallbackReturn.SUCCESS
        except Exception as e:
            self.get_logger().error(f'Configure failed: {e}')
            return TransitionCallbackReturn.FAILURE

    def on_activate(self, state: LifecycleState) -> TransitionCallbackReturn:
        """开始发布数据"""
        self.timer = self.create_timer(0.02, self.publish_data)
        return TransitionCallbackReturn.SUCCESS

    def on_deactivate(self, state: LifecycleState) -> TransitionCallbackReturn:
        """暂停发布"""
        self.destroy_timer(self.timer)
        return TransitionCallbackReturn.SUCCESS
```
5.Demo：Lifecycle节点+手动触发状态转换+ros2 lifecycle命令。
6.数据流：外部命令 → Lifecycle Manager → 状态转换 → 回调执行 → 节点就绪。
7.调试手段：ros2 lifecycle list/get/transition手动控制状态；Nav2的Lifecycle Manager自动管理。
8.故障：节点配置失败后无法恢复——根因：on_configure返回FAILURE后状态停在Unconfigured；修复：清理资源后重新触发configure。
9.工业案例：Nav2所有节点都是Lifecycle Node，启动时按依赖顺序依次activate，任一失败则整体回退。

## 第50课 DDS网络配置、多机通信与延迟优化
1.业务背景：多机器人协同或工控机+边缘计算分离部署时，DDS网络配置决定通信可靠性和延迟。
2.底层原理：DDS网络核心——(1)Domain ID：同Domain的节点可互相发现，不同Domain隔离；(2)多播(Multicast)：默认使用多播发现节点，跨网段需配置中继；(3)共享内存(SHM)：同机节点使用共享内存零拷贝传输，降低CPU和延迟；(4)UDP单播回退：多播不通时自动回退。FastDDS配置：XML profile调优(participant/transport/flow_controller)。
3.硬件方案：本项目多机方案——工控机+边缘GPU盒子，千兆以太网直连，Domain 0。
4.软件实现：FastDDS XML配置+多机发现设置。
```xml
<?xml version="1.0" encoding="UTF-8"?>
<profiles>
    <participant profile_name="robot_participant">
        <rtps>
            <useBuiltinTransports>false</useBuiltinTransports>
            <!-- 共享内存传输 (同机) -->
            <builtinTransports>
                <shm_transport>
                    <prefix>fast_shm</prefix>
                </shm_transport>
            </builtinTransports>
            <!-- UDP传输 (跨机) -->
            <builtinTransports>
                <udp_transport>
                    <sendBufferSize>1048576</sendBufferSize>
                    <receiveBufferSize>4194304</receiveBufferSize>
                </udp_transport>
            </builtinTransports>
        </rtps>
    </participant>
</profiles>
```
5.Demo：FastDDS XML配置+两机通信测试+延迟测量。
6.数据流：Publisher → SHM(同机) / UDP(跨机) → Subscriber。
7.调试手段：FASTRTPS_DEFAULT_PROFILES_FILE指定XML；ros2 topic delay测量端到端延迟；iperf3测网络带宽。
8.故障：跨机节点互相看不到——根因：多播被路由器过滤；修复：配置ROS2_PEER环境变量指定对端IP单播发现。
9.工业案例：某多AMR系统同机导航+视觉用SHM传输图像(延迟<1ms)，跨机用UDP(延迟<5ms)。
10.面试题：DDS Domain和Discovery机制？SHM零拷贝原理？跨网段如何配置ROS2通信？
